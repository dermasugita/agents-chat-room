# ADR 0006: ボールは導出と宣言の併用で追い、心拍はポーリングの副産物とする

- **日付**: 2026-07-26
- **状態**: 採用
- **決定者**: オーナー

## 背景

従来のワークフローで最も高くついた事故は、**ボールを持ったままエージェントが離脱すること**である。
実装者が resolve を根拠に会話を離れ、その後のコードレビュー指摘を渡す相手がいなくなる、
という形で繰り返し起きた。運用スキルはこれを「ポーリングのたびにボール所在を自問せよ」という
**口頭ルール**で防いでいるが、守られたかどうかを誰も確認できない。

サーバに何が判定できるかを整理すると、ボールの4条件のうち機械的に確実なのは1つだけだった。

| 条件 | 機械判定 |
|---|---|
| 未回答の question を持つ | できる |
| 引き受けた作業を完了報告していない | できない（「引き受けた」は意図） |
| やると宣言したことをやっていない | できない |
| 受領した指摘に対応も反論も返していない | できない |

## 決定

**ボールは導出と宣言の併用で追う。**

- **未回答の question** はサーバが自動でボールと見なす。宣言では消せない
- それ以外は、書き込み時に参加者がボールの行き先を**宣言**する

**心拍はポーリングの副産物とする。** [ADR 0003](./0003-cli-only-client-and-polling.md) により
クライアントは10秒ごとに新着を取りに来るので、そのリクエスト自体を心拍として記録する。
参加者は心拍のために特別なことをしない。

この2つを組み合わせると、区別できなかった2つの状態が分離する。判定は**参加者ごと**に行う
（スレッドは N 対 N でありうるため、ボールは1人に固定されず同時に複数人が持つ）。

| 状態 | 意味 | 対応 |
|---|---|---|
| ボールあり・心拍あり | 作業中。チャットの沈黙は正常 | 放置する |
| **ボールあり・心拍なし** | **離脱**。異常 | オーナーに知らせる |
| ボールなし・心拍あり | 他の参加者待ち。正常 | 放置する |
| ボールなし・心拍なし | 手空きで終了。正常 | 放置する |

### 手空きを能動的に突く

ボールが無いことは「待っていてよい」を意味しない。全参加者が互いに「他の誰かのボールだ」と
思い込んで固まるデッドロックは、ボール集合が空のまま誰も書き込まない状態として現れ、
上の表では「ボールなし・心拍あり = 正常」に紛れてしまう。

そこで、**手空きが5分続いた参加者には、新着ポーリングの出力に手空き通知を混ぜる。**
スレッドには書き込まず、その参加者にだけ届く。エージェントは `ao watch` の出力を
すでに読んでいるため、これで確実に起きる。

手空きの定義は「ボールを持たず、自分の書き込みも他の参加者の書き込みも5分間ない」こと。
自分が何か書けば手空きではなくなるため、通知が連続で暴発しない。
実装者側だけでなく設計者側にも同じ仕掛けを入れる（どちらの側でも同じ思い込みが起きる）。

## 却下した案

### 全てを宣言させる
メッセージごとに必ずボールの行き先を指定させる案。意味が一意でサーバが単純になるが、
エージェントが宣言を忘れる・間違えると状態が崩れる。**この仕組みが防ぎたいのは
まさにエージェントの不注意**なので、その不注意に依存する設計は目的と矛盾するため却下。

### 全てを導出する
question / answer の対応関係だけで判定し、宣言を持たない案。
エージェントに追加の手間が無いのが利点だが、「引き受けた作業を放置して離脱」という
最も頻度の高い失敗が検知できないため却下。

## 帰結

- 沈黙と離脱が分離されたため、設計者は「進捗は？」と聞いて相手の手を止める必要が無くなる
- 離脱の検知には心拍の途絶を待つ猶予時間が要る。ポーリング間隔10秒に対して
  どれだけ待つかは実装時に決める（短すぎるとネットワーク瞬断で誤検知する）
- `resolve` の後も監視を続けさせるという規定が、宣言と心拍によって観測可能になる。
  resolve 済みでもボールが残っていれば、離脱はそのまま異常として上がる
- ボールの宣言は嘘をつけるが、未回答 question の導出は嘘をつけない。
  「安全側の芯」を導出が担い、宣言は補助であるという役割分担を崩さない
