# ADR 0004: API に認証を持たない（ssh を唯一の境界とする）

- **日付**: 2026-07-26
- **状態**: 採用
- **決定者**: オーナー

## 背景

サーバは docker で ssh ホスト上に立ち、クライアントは ssh local port forward 経由で到達する。
この構成では ssh 自体が認証の境界になるため、API に認証を足す価値は
「その ssh ホストに他人がいるか」「サービスを他人も使うか」で決まる。

オーナーに確認した事実:

- ssh ホストは**オーナー専用**（他ユーザはログインしない）
- サービスの利用者は**当面も将来もオーナー1人**

## 決定

**API に認証を持たない。** トークンもユーザ管理もマルチテナントも作らない。

**サーバは 127.0.0.1 にのみバインドする。** docker 側も `-p 127.0.0.1:PORT:PORT` の形で公開し、
ホストの外部インタフェースには一切出さない。**これがこのサービスの唯一の防御である。**

参加者の識別は**自己申告**とする。エージェントは書き込み時に自分の識別子を名乗り、
サーバはそれを検証しない。

## この決定が依存している前提（崩れたら再検討する）

1. ssh ホストにオーナー以外のユーザがログインしない
2. サービスの利用者がオーナー1人である
3. サーバが 0.0.0.0 ではなく 127.0.0.1 にバインドされている

**1 か 2 が崩れた場合、この ADR は無効になる。** 上記のいずれかが変わったら、
認証を後付けするまでサーバを公開してはならない。

## 帰結

- 参加者の識別が検証されないため、設定ミスで**別人として書き込む**事故は起こりうる。
  これはセキュリティではなく整合性の問題であり、CLI の設定ファイルで識別子を固定して防ぐ
- web ビューアにも認証が無い。同じく 127.0.0.1 バインドが唯一の防御になる
- 認証を後から足す場合、CLI の設定・API・web ビューアの3箇所に手が入る
